Вставь целиком первым сообщением в сессию Arena Agent Mode на репозитории `Leo88q/investor`.

---

## 0. Контекст и подключение хаба

```bash

cat /tmp/watchtower-hub/INVESTOR_LANDING_BRIEF.md          # бриф: оффер, формулы, копирайт RU/EN, токены
```

## 1. Главный принцип приложения

**Ноль выдуманных чисел.** Лендинг продаёт право на 25% чистой прибыли студии, поэтому любая цифра
обязана быть либо (а) получена из hub API с `source` и `dataQuality`, либо (б) явно помечена как
«DEMO DATA» / «в работе» / «плановый ориентир». Сегодня студия на уровне L1: `configured: 0 из 5`,
данные mock — лендинг не имеет права показывать их как реальность.

## 2. W1 — честный контур данных (P0)

1. Все показатели (игроки, объёмы, выручка, retention, трафик) берутся из:
   - `GET /api/investors/report`, `/api/investors/snapshots`, `/api/investors/trend` — финансовая часть;
   - `GET /api/ecosystem/status` — уровень/подключённость каждой игры (**появится после `PROMPT_MAX_HUB.md`**);
   - `GET /api/read-model` — сводные метрики;
   - `GET /api/analytics/traffic` — acquisition.
2. Каждое число в UI несёт бейдж: `complete` / `partial` / `unavailable` + `asOf` (время) + ссылку
   «откуда» (источник). Mock-режим (`source: 'mock'`) отображается только с бейджем **DEMO DATA**.
3. Экран «Состояние студии»: 4 игры + приложения, уровни L0–L4, что подключено, что нет и почему.
   Это защищает инвестора от иллюзий и защищает студию от претензий.
4. Снапшоты и дивиденды: формула из брифа
   (`Дивиденд на NFT за квартал = (Чистая прибыль студии за квартал × 25%) / 100`), даты снапшотов
   (1 янв/апр/июл/окт при рабочем дне), получатель — актуальный владелец NFT. Для каждого
   подтверждённого квартала — ссылка на снапшот-запись (`/api/investors/snapshots`) и источник прибыли;
   кварталы без прибыли показываются как `0` с пояснением, а не скрываются.
5. Никаких «обещанных» доходностей, только исторические данные и явно помеченные ориентиры
   («не обещание»), как требует бриф.

## 3. W1 — юридическая и продуктовая честность

1. Дисклеймер: NFT даёт право на долю прибыли по описанной формуле, не является ценной бумагой/долей
   в компании по применимому праву; выплаты — on-chain USDC по расписанию; риск потери стоимости.
2. KYC/AML-политика и ограничения по юрисдикциям — на лендинге, с формулировками, согласованными
   оператором (вопрос в разделе F отчёта, если политики ещё нет).
3. Лимит 10 NFT на кошелёк — отображается как параметр дропа; при изменении параметра обновляется
   в одном месте (`src/config.js`), а не в тексте.
4. Прозрачность mint: адрес программы минта и supply (100) публикуются после подтверждения оператором;
   до этого — статус «в работе», без фейковых адресов.

## 4. W2 — фронтенд-качество до L3

- `f-01`/`f-02`: бейджи `dataQuality` и трассируемость каждой метрики (источник, формула, `asOf`, часовой пояс).
- `f-10`: RU/EN переключатель без потери состояния, клавиатурная навигация, aria для всех интерактивных
  блоков и формы заявки.
- `f-11`: LCP < 2.5 c, bundle < 200 kB gzip, изображения в современном формате и с размерами
  (`public/images/*.webp` уже есть), отсутствие блокирующих ресурсов.
- `f-12`: честные состояния — если API недоступен, показывается «данные недоступны» с причиной,
  никогда не подставляются старые или выдуманные значения; ошибки формы с понятными сообщениями.
- `f-08`: SSE/WS не обязательны, но обновление данных должно иметь явное время последнего обновления.
- Доступность форм: валидация, защита от спама, сохранение согласия (`consents`) и передача лида
  в студию через контракт, а не «в никуда».

## 5. W2 — тесты и поставка

1. `tests/math.test.js`: формулы дивиденда, доли 0.25%, 25% пула, округления вниз/вверх — покрыть
   границы (нулевая прибыль, отрицательная прибыль, максимальный supply).
2. `tests/browser/*.spec.js` (Playwright): бейдж DEMO DATA на mock-данных; отсутствие числа без
   бейджа; RU/EN переключение; форма заявки; поведение при недоступном API; `axe`-проверки доступности.
3. `scripts/seo.mjs`: OG/Twitter-карточки, sitemap, canonical, JSON-LD — с текущими данными, без
   заявления несуществующих метрик.
4. CI: сборка + тесты + проверка «нет чисел без источника» (кастомный линтер/тест, который ищет
   в контенте цифры и требует для каждой либо API-поле, либо пометку).

## 6. W3 — переплетение

```text
i-09 аналитика     acquisition-метрики берутся из trafficgen (funnel ad_click → wallet → first_action)
i-08 кампании      конверсия лендинга (visit → заявка → покупка NFT) уходит в общий отчёт кампаний
i-02 согласия       согласие из формы и opt-out синхронизированы с consent-сервисом студии
i-05 экономика     правила распределения прибыли от игр совпадают со studio treasury-политикой:
                   инвестор видит ту же формулу, по которой считает хаб
i-13 экран статуса экосистемы на /api/ecosystem/status (тот же источник, что в хабе)
```

## 7. W4 — hot

- **SLO** (`o-02`): uptime ≥ 99.9%, p95 загрузки из API ≤ 300 мс, отчёты о доступности публично.
- **DR/ops** (`o-05`, `o-06`): бэкап контента и конфигов, SBOM зависимостей, регламент релиза и откат.
- **Forensics** (`o-07`): журнал заявок и согласий, кто и когда публиковал числа (публикация снапшота —
  только после подтверждения оператором, с audit-записью).
- **Комплаенс**: при выходе в публичный mint — юридическая проверка формулировок и юрисдикционных
  ограничений (вне зоны AI, фиксируется как operator decision).

## 8. Definition of Done

```text
[ ] Ни одно число не отображается без source + dataQuality + asOf
[ ] Mock-данные видны только с бейджем DEMO DATA; планы — «в работе»/«не обещание»
[ ] Экран «Состояние студии» на /api/ecosystem/status (уровни, подключённость, причины)
[ ] Снапшоты/дивиденды: формула из брифа, ссылки на записи снапшотов, нулевые кварталы показаны
[ ] Дисклеймер и ограничения по юрисдикциям опубликованы
[ ] Тесты: math (границы), browser (бейджи, RU/EN, форма, API недоступен, a11y), линтер «нет чисел без источника»
[ ] Lighthouse: LCP < 2.5 c, bundle < 200 kB gzip; SEO/OG/JSON-LD корректны
[ ] Контуры i-09, i-08, i-02, i-05 с тестом/доказательством
[ ] PR в arena/*, main не изменён, секретов и приватных ключей нет
```

## 9. Формат ответа

A–F из `00_HUB_CONTRACT.md` §7. В разделе F обязательно перечисли вопросы оператору: юридическая
структура (какой субъект, какая юрисдикция), KYC/AML-провайдер, налоговая логика выплат, статус
mint-программы и мультисига. Секреты и приватные ключи минта в репозитории не появляются ни при
каких условиях.
