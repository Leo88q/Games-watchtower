# Аудит-промпты: как проверять работу независимым агентом

Три промпта для **внешнего** AI-агента (не автора работы). Все read-only: аудитор ничего не меняет,
не коммитит, не пушит, не трогает `main` и не отправляет транзакций.

| Файл | Область | Когда использовать |
|---|---|---|
| `PROMPT_AUDIT_INDEPENDENT.md` | только гид-хаб `Leo88q/Games-watchtower` | быстрая независимая проверка хаба: 18 утверждений автора (C1..C18), экономические метрики, честность данных, тесты |
| `PROMPT_AUDIT_PRODUCTION_DEEP.md` | только гид-хаб `Leo88q/Games-watchtower` (v2 к `PROMPT_AUDIT_INDEPENDENT`) | глубокий аудит перед продакшн-деплоем: уязвимости, баги, несостыковки, фиктивные тесты, пробелы эксплуатации; журнал покрытия, мутационные проверки, вердикт `GO / GO-WITH-CONDITIONS / NO-GO` |
| `PROMPT_AUDIT_FULL_STACK.md` | вся экосистема: хаб + 4 игры + трафик-приложение + инвесторский лендинг (7 репозиториев) | глубокий аудит перед продакшн-деплоем: логика, типизация, безопасность, функционал, баги, дыры, несостыковки, упущения, битые файлы, экономическая модель, прогон **всех** тестов |

## Как запускать аудит хаба

```text
Сессия 1 : вставить PROMPT_AUDIT_PRODUCTION_DEEP.md целиком — внешний агент с shell
           (git, node, npm, python3, curl) и клоном Leo88q/Games-watchtower
Сессия 2 : повторный аудит тем же промптом (§16) — после исправлений, для проверки закрытия находок
```

`PROMPT_AUDIT_INDEPENDENT.md` — его короткая версия (без фаз атак, мутаций и деплой-гейтов).

## Как запускать полный аудит

```text
Сессия 1..7 : по одной на репозиторий — вставить PROMPT_AUDIT_FULL_STACK.md целиком
              + строку репозитория из таблицы §1 этого промпта
Сессия 8    : консолидатор на Leo88q/Games-watchtower — собрать 7 отчётов в сводный (§7.2)
```

Порядок по риску: `guttercaps` → `talkchart-traffic-generator` → `aof` → хаб → `ares1` →
`neon-relay` → `investor`, затем сводная сессия.

## Правила для аудитора (общие для обоих промптов)

1. Аудируется **конкретный коммит**, хеш — в шапке отчёта.
2. Документы и README — утверждения подсудимого, а не доказательства.
3. Каждая находка = команда + дословный вывод + место в коде + ожидание из claim.
4. Нет данных → `unverifiable` с причиной; нули и догадки вместо отсутствующих данных запрещены.
5. Тесты: прогнать все найденные команды, дважды (flaky), плюс мутационная проверка — тесты,
   которые проходят на сломанном коде, считаются находкой.
6. Секреты — только место и тип, значения не публикуются; история git проверяется отдельно.
7. Декларация выборки обязательна: что покрыто полностью, что частично, что вне аудита.

## Артефакты аудита

- `AUDIT_<repo>_<YYYY-MM-DD>.md` — отчёт по репозиторию (§7.1 полного промпта).
- `audit-<repo>-<YYYY-MM-DD>.json` — машиночитаемая сводка.
- Сводный отчёт и `audit-ecosystem-<date>.json` (§7.2) складываются оператором в хаб,
  например `reports/audit-<YYYY-MM>/`. Аудитор в чужие репозитории ничего не коммитит.
