# Финальная модель безопасности и доступа операторского центра Watchtower
Реализовано и готово к продакшену по итогам аудита.

## Принцип нулевого доверия
1.  Никакие прямые записи в блокчейн или игровые бэкенды из интерфейса операторов не выполняются.
2.  Никакие действия не применяются без консенсуса и подтверждения дежурным сотрудником для всех рисков выше безопасного.
3.  Доступ исключительно реальным игрокам с прогрессом в играх студии.
4.  Экономическая нецелесообразность любых атак через высокую стоимость Sybil-атак (прокачка игровых аккаунтов).

## Защита от угроз
| Угроза | Защита |
|---|---|
| Сибилл-атаки фейковых кошельков | Требуется реальный игровой прогресс и часы в играх, проверка истории аккаунта от 30 дней. Стоимость создания 1000 аккаунтов оценивается в тысячи часов игрового времени. |
| Голосование в областях где оператор не разбирается | Голос имеет полный вес только в играх где у оператора есть ранг, в остальных вес снижен на 70%. |
| Олигархия топов/киты решают всё | Логарифмический вес голоса, жёсткий потолок 5 на любого не сотрудника, нет возможности купить вес. |
| Ложная тревога и пауза контракта по вине толпы | Минимальный абсолютный порог взвешенных голосов для каждого действия, обязательное одобрение двух сотрудников для критических действий, задержка показа критических инцидентов на 2 минуты для фора команды, кулдаун от 30 минут на повторные действия в одной игре. |
| Инсайдерская торговля по информации из центра | Детали критических уязвимостей скрываются до разрешения, показываются только общие формулировки. Мониторинг кошельков операторов на предмет инсайдерских сделок, при детекции — вечный бан и отмена выплат. |
| Дос/спам голосов | Рейт-лимиты: максимум 12 голосов в час на кошелёк, бэтчевая запись в базу, защита от повторных запросов. |
| Сговор группы операторов | Детекция скоординированных голосов по IP, связанным транзакциям и истории совпадений голосов. При подтверждении сговора — вечный бан, потеря репутации и залога (если есть), награда за репорт сговора тому кто его обнаружил. |
| Случайные ошибки | Нет штрафов залогом за обычные ошибки, только небольшое снижение репутации. Порог точности автоматически понижает в ранге операторов с точностью ниже пороговой. |
| Ночные атаки при низком онлайне | Автоматическое исполнение отключено для всех действий кроме безопасных в период с 2 до 8 утра, требуется обязательное подтверждение сотрудника независимо от консенсуса. |
| Подделка кошелька | Авторизация через подпись nonce, невозможно зайти под чужим кошельком без приватного ключа. |

## Монетизация и выплаты
1.  Плата за вход отсутствует. Доступ даётся исключительно за реальный игровой прогресс.
2.  Опциональный стейкинг SOL удваивает вес голоса и выплаты, но не даёт никаких преимуществ в ранге и доступе без игрового прогресса. Залог возвращается при уходе, не платится студии.
3.  Выплаты производятся из общего баунти-фонда:
    - 5% всех доходов студии с игр
    - 10% от суммы предотвращённого ущерба за исправленный эксплойт
    - Добровольные донаты сообщества
4.  Выплаты распределяются пропорционально весу голоса, скорости реагирования и точности операторов, автоматически на кошелёк раз в неделю.
5.  Выплаты доступны только операторам и выше, с точностью голосов не ниже 75%, без активных штрафов.
6.  Категорически не продаётся: ранги, вес голоса, доступ к инцидентам раньше других, любые игровые преимущества. Только косметика и профили (значки, рамки, темы интерфейса).

## Оставшиеся интеграции перед продом
1.  Отправка отчётов о прогрессе со стороны самих игр. Приём на вахте готов (`POST /api/games/progress` с HMAC и опрос API игры), но каждая игра должна получить свой секрет и начать присылать данные.
2.  Подключение реальных вебхуков исполнения действий (Cloudflare, статус-страница, мультисиг)
3.  Подключение KYT для проверки кошельков на грязные средства
4.  Система уведомлений дежурных и браузерные пуш-уведомления для операторов
5.  Система апелляций и детекции сговора

## Дополнение: путь игрока до права голоса (октябрь 2026)

- **Вход на вахту** (`POST /api/operator/auth`) отмечает кошелёк как подключённый. Игрок с 10+ часами и рангом 2 в любой игре студии становится **Кандидатом**.
- **Проверка правил** (`GET/POST /api/operator/exam`): 5 вопросов, ключ ответов только на сервере, проходной балл 4 из 5, после провала повтор через 10 минут. Сдача вместе с прогрессом в игре даёт роль **Наблюдателя** (голоса без риска и низкого риска).
- **Классификация маршрутов:** `POST /api/operator/{nonce,auth,vote,approve,exam}` относятся к типу `operator`. Они пишут только в журнал голосования вахты (`data/operator-game`), не в игры и не в блокчейн. Поэтому проходят как чтение (read-токен, если задан) и защищены собственными лимитами модуля. Все остальные POST по-прежнему требуют ingest-токен или HMAC.
- Тревоги детекторов (`/api/alerts`) показываются на карте как информация и не становятся предметом голосования. Аномалией для вахты считается только зарегистрированный инцидент.

## Дополнение: подпись кошелька, прогресс из игр, PostgreSQL и Redis (октябрь 2026)

- **Вход только подписью.** Сервер выдаёт сообщение с одноразовым кодом (5 минут), кошелёк подписывает его ed25519, сервер проверяет подпись против адреса Solana и забирает код один раз. Повтор подписи и подбор к тому же коду невозможны. Подробности: `docs/OPERATOR_GAME_DEPLOYMENT.md`.
- **Сессия вместо адреса в теле.** Голос, подтверждение и проверка правил требуют подписанную HMAC сессию в заголовке `x-operator-session` (12 часов). Кошелёк берётся из сессии, поэтому голосовать от чужого адреса нельзя.
- **Демо-вход** (`test_wallet`, `demo*`) работает только вне продакшена и при включённом демо-режиме. В продакшене он выключен независимо от флагов.
- **Реальный прогресс.** Часы и ранги приходят из игр: игры присылают подписанные HMAC отчёты, либо вахта опрашивает API игры при входе. Демо-прогресс выдаётся только демо-кошелькам в разработке. У настоящего адреса без данных из игр роль «Гость».
- **PostgreSQL и Redis.** Состояние вахты хранится в PostgreSQL (`DATABASE_URL`), коды входа и лимиты — в Redis (`REDIS_URL`). Без них остаются файлы и память процесса. Запись голосов пока должна идти через один экземпляр API, см. «Ограничение масштабирования».
