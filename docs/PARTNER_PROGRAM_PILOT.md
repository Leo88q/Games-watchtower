# Партнёрская программа: пилот

Игроки, авторы видео и партнёры по трафику приводят новичков в игры Leo Games. Награда начисляется
**за игрока, который остался в играх**, а не за клик, установку или регистрацию. Вахта только считает
и показывает. Деньги переводит студия вручную и отмечает выплату ссылкой на перевод.

Партнёрство не даёт доступа к ролям вахты. Роли по-прежнему открываются только часами и рангами в играх.

## Кто участвует

| Тип | Как вступить | Ставка в пилоте |
|---|---|---|
| Игрок | сам, от `PARTNER_MIN_REFERRER_HOURS` (10) часов в играх студии | 1 USDC за игрока |
| Автор видео и нарезок | заявка с каналом, одобряет сотрудник | 3 USDC за игрока |
| Партнёр по трафику | заявка с источником трафика, одобряет сотрудник | 2 USDC за игрока |

На каждый кошелёк приходится одна запись партнёра. Код состоит из 8 символов, без похожих 0/O/1/I.

**Ставки и актив — заглушки пилота**, пока студия не выбрала валюту, игру, регион и бюджет. Все значения
задаются переменными `PARTNER_*` в `.env.example`.

## Путь игрока

1. Партнёр делится ссылкой `https://<хаб>/r/<КОД>`. Переход считается уникальным за день по хэшу IP (адрес
   не хранится) и ведёт на карту `/?ref=<КОД>`. Переходы показываются только для информации, за них не платят.
2. Карта запоминает код на 30 дней (первый пригласивший остаётся) и добавляет `?ref=<КОД>` к ссылкам
   «Сайт игры».
3. Привязка — **один раз и только новичку** (меньше `PARTNER_NEW_PLAYER_MAX_HOURS` = 2 ч во всех играх на момент
   привязки). Варианты:
   - игра присылает `ref` в подписанном отчёте `POST /api/games/progress`, это основной путь;
   - игрок входит на вахту, и интерфейс отправляет `POST /api/partners/claim`.
   Себя пригласить нельзя, взаимные приглашения (A→B, B→A) не засчитываются.
4. **Квалификация** — за `PARTNER_WINDOW_DAYS` (30) дней после привязки нужно прибавить `PARTNER_QUALIFY_HOURS` (2) ч
   и быть активным в `PARTNER_QUALIFY_DAYS` (3) разных дня. День активности — это день, когда игра подписала
   отчёт с ростом часов (`updatedAt` отчёта). Время сервера здесь не используется, поэтому повтор отчёта
   дней не добавит.
5. **Заморозка**: награда фиксируется по ставке на момент квалификации и держится `PARTNER_HOLDBACK_DAYS` (14) дней.
   Если игрока за это время заблокируют, награда аннулируется.
6. После заморозки награда переходит в статус «к выплате». Сотрудник переводит деньги и отмечает выплату ссылкой
   на транзакцию.

Статусы приглашения: `tracking` → `holdback` → `payable` → `paid`; также `void` (аннулировано) и `expired` (окно истекло).

## Защита от накрутки

- Платим только за часы, подписанные играми (HMAC), а не за клики.
- Новичок определяется по часам во всех играх, привязка разрешена один раз.
- **Дневной лимит** `PARTNER_DAILY_CAP` (30) квалификаций на партнёра в сутки. Если он превышен, партнёр уходит
  на ручную проверку, и пока сотрудник не снимет проверку, награды не размораживаются.
- Блокировка партнёра аннулирует все незаплаченные награды.
- Запрещено: платить игрокам за установку (incentivized traffic), покупать рекламу по названиям игр студии,
  обещать заработок, выдавать ссылку за раздачу токенов.
- Кошельки приглашённых в кабинете партнёра укорочены.

## API

| Метод | Доступ | Назначение |
|---|---|---|
| `GET /r/<код>` | все | учёт перехода и редирект на карту; неактивный код ведёт на `/` |
| `GET /api/partners/rules` | все | публичные правила и ставки |
| `GET /api/partners/me` | сессия | кабинет: код, статус, сводка, приглашённые, переходы за 30 дней, кто пригласил вас |
| `POST /api/partners/join` | сессия | `{ kind: "player" \| "creator" \| "traffic", channel? }` |
| `POST /api/partners/claim` | сессия | `{ code }`: привязка новичка |
| `GET /api/partners/review` | сотрудник | заявки, партнёры на проверке, суммы к выплате с полными кошельками |
| `POST /api/partners/decide` | сотрудник | `{ action, code, reference?, reason? }` |

Действия сотрудника: `approve` / `reject` (заявка), `clear` (снять проверку), `ban`, `void` (одно приглашение,
`wallet`), `paid` (всё «к выплате» у партнёра, `reference` от 4 символов). Все записи идут через общую блокировку
хранилища (`operatorWrite`) и поэтому безопасны при нескольких экземплярах API.

Данные хранятся в разделах `partners` и `referrals` таблицы `watchtower_state`. Счётчики переходов лежат в общем
кэше (Redis): `ref-clicks:<код>:<день>`, срок хранения 40 дней.

## Что нужно от игр

Передать код из `?ref=` на сайте игры в первый подписанный отчёт игрока:

```json
{ "reports": [ { "wallet": "<адрес>", "hours": 0.3, "rank": 0, "updatedAt": 1791216000000, "ref": "K7M2Q9XA" } ] }
```

Код в следующих отчётах не обязателен. Если игрок уже не новичок, код просто игнорируется.
