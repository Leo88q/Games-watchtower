# Watchtower OS — гайд по продукту (что готово, что нет, как запускать)

Документ описывает **фактическое** состояние продукта на 2026-09-23 и разъясняет каждую функцию
интерфейса. Ни одно утверждение здесь не является обещанием: всё либо проверено командой, либо
помечено как задача оператора.

## 0. Короткий ответ на вопрос «всё готово к продакшену?»

**Нет.** Готово ядро платформы (read-only API с токенами доступа, интерфейс, промпты, спецификация, проверки).
Готов также движок **экономических метрик** (40 метрик в 8 семействах, 13 автотестов) — он честно
работает от принятых событий и помечает недоступное как `unavailable`.
Не готово главное для «тёплого продукта»: **ни одна игра не подключена** — `configured: 0 из 5`,
источник данных — `event-inbox` (события игр через `POST /api/ingest/*`). Пока игры не подключены,
аналитика, экономика и cross-game контуры физически не работают: метрики возвращают `unavailable` с причиной,
а не нули. Синтетический поток доступен только по `?demo=1`, помечен `DEMO DATA` и в production выключен.

Что именно мешает — видно на экране **«Деплой»** и в разделе ниже «Что требует оператора».

## 1. Как запустить продукт

```bash
npm install
npm run build          # собирает dist/ (ios.html + index.html)
node server/index.js   # один порт: API + собранный интерфейс
# → http://localhost:8787
```

Режим разработки с автоперезагрузкой (два процесса):

```bash
node server/index.js &   # API на 8787
npm run dev              # Vite на 5173, проксирует /api и /metrics на 8787
```

Проверки:

```bash
npm run test:smoke              # контракт приёма и safety-гейты
npm run ecosystem:target        # фактические уровни L0..L4 по tenant'ам
npm run ecosystem:target:strict # гейт: покрытие L3+ не ниже цели (сейчас падает — это честно)
```

## 2.1. Статус по функциям: готово / частично / ожидает оператора

| Функция | Статус | Чем подтверждается | Что мешает |
|---|---|---|---|
| Приём и дедупликация событий | **готово** | `npm run test:smoke` PASSED | — |
| Реестр игр и приложений (5 объектов) | **готово** (структура) | `/api/games`, `/api/ecosystem/status` | нет боевых данных: `configured 0/5` |
| Уровни зрелости L0..L4 | **готово** (расчёт) | `npm run ecosystem:target` | L3+ 0% при цели 80% |
| Безопасность: находки аудита | **частично** | `reports/*-audit.json` | сканы ares1 и neon-relay пустые (`files_scanned: 0`) |
| Опасные действия (proposal-flow) | **готово** (политика) | `/api/control/policy`, `/api/audit` | исполнение — только оператором с multisig |
| Аналитика: трафик и воронка | **частично** | `/api/analytics/traffic`, `/api/funnels` | нет эмиттера трафика (`TRAFFICGEN_API_BASE_URL`) |
| Аналитика: AI-отчёт | **частично** | `/api/ai/report` | выводы строятся на событиях inbox; при отсутствии данных ответ содержит причину |
| Переплетение игр (cross-game) | **ожидает данных** | `/api/players/cross-game`, семейство `cross` | нужны подключённые игры |
| Экономические метрики (40) | **готово**, ждёт данных | `/api/economy/overview`, `npm run test:economy` (13 тестов) | боевой режим честно `unavailable`: события не поступают; часть метрик требует ENV-фактов |
| Инвесторский контур | **готово** (каркас) | `/api/ecosystem/report`, `/api/investors/report` | цифры считаются по событиям inbox; недоступные поля — `null` с причиной и `dataQuality` |
| Промпты Arena (13) | **готово** | `/api/arena/prompts`, кнопка «Приступить» | — |
| Интерфейс (9 разделов) | **готово** | собранный `dist/`, живой сервер :8787 | — |
| Деплой (Docker / Node) | **готово** (упаковка) | `Dockerfile`, `dist/` | нет хостинга, домена, TLS — задача оператора |
| Спецификация и гейты | **готово** | `docs/ecosystem-target.spec.json`, `ecosystem:target:strict` | строгий гейт падает честно: L3+ 0% |
| Документация | **готово** | `README.md`, этот гайд, `docs/ECONOMY_METRICS_V1.md` | — |

Итог по функциям: **всё, что не зависит от внешних данных, доработано**; частично работают только
аналитика и аудиты (нет эмиттеров и сканов), а экономические метрики готовы и включаются сами,
как только в хаб пойдут события игр.

## 3. Новые маршруты API (добавлены в этой версии)

```text
GET /api/ecosystem/status     — уровни L0..L4 по tenant'ам, покрытие цели, суммы findings,
                                список объектов с невыполненным сканом
GET /api/ecosystem/report     — машинный свод для отчётов и лендинга: подключено/не подключено,
                                причины, dataQuality отчёта (complete|partial|unavailable)
GET /api/arena/prompts        — каталог 13 промптов Arena (минимум и максимум)
GET /api/arena/prompts/:id    — текст промпта (для кнопки «Приступить»)

GET /api/economy/overview     — 40 экономических метрик, индекс здоровья, входные данные
                                (?window=24h|7d|30d|90d, ?gameId=..., ?demo=1 — DEMO DATA)
GET /api/economy/health       — только индекс и входные данные (для мониторинга)
GET /api/economy/catalog      — каталог метрик с формулами, источниками и нужными событиями
```

Все семь — read-only и не требуют секретов. Сервер также раздаёт собранный `dist/`
(маршрут `/` → `ios.html`), поэтому продукт можно поднять одним сервисом.

## 4. Контракт безопасности (не меняется без решения оператора)

- **Ни одного блокчейн-write из хаба.** Ни одного signer'а в процессе.
- Опасные действия — только proposal-flow: RBAC, 2FA, второе подтверждение, multisig/timelock,
  audit log, rollback.
- Приватные ключи, seed-фразы, upgrade authority, treasury/reward signer'ы и admin-токены
  в репозиторий и в хаб не попадают никогда.
- Секреты — только именами переменных окружения (`.env.example`), значения задаёт оператор.
- Доступ к API — `WATCHTOWER_READ_TOKEN` (Bearer, сравнение constant-time, ротация `_PREVIOUS`).
- PII не собирается: кошельки и идентификаторы псевдонимизируются с солью.

## 5. Что требует оператора (блокеры тёплого состояния)

| # | Блокер | Что нужно | Почему без этого нельзя |
|---|---|---|---|
| 1 | Program ID игр не заданы | Подтвердить адреса через RPC и внести в окружение: `ARES1_PROGRAM_ID`, `AOF_CORE_PROGRAM_ID`, `NEONRELAY_REWARDS_PROGRAM_ID`, `GUTTERCAPS_CORE_PROGRAM_ID` | Без адреса адаптер не может читать события: `configured: false` |
| 2 | Экспортер трафика | `TRAFFICGEN_API_BASE_URL` + `WATCHTOWER_READ_TOKEN` | Аналитика acquisition остаётся пустой |
| 3 | Аудиты ares1 и neon-relay | Запустить сканер на актуальных клонах | Публиковать «43» и «24» находки без скана нельзя |
| 4 | 90 critical в играх | Закрыть по промптам `PROMPT_MAX_*` | Критические уязвимости контрактов угрожают активам игроков |
| 5 | Хостинг и домен | Аккаунт (Node-хостинг или VPS) + домен + TLS | Локальный запуск не является деплоем |
| 6 | Юридические решения | Юрисдикции, KYC/AML, лицензия 698 ассетов Neon Relay | Вне зоны AI: решения владельца |

## 6. Деплой: как это делается

**Вариант A — Docker (рекомендуется).**

```bash
docker build -t watchtower-os .
docker run -p 8787:8787 --env-file .env watchtower-os
```

**Вариант B — Node-хостинг (Railway/Render/Fly/VPS).**

```bash
npm ci && npm run build
node server/index.js        # старт-команда
# порт задаётся переменной API_PORT (по умолчанию 8787)
```

**Вариант C — статика отдельно.** `dist/` можно раздавать на любом CDN, но API всё равно
требуется отдельным сервисом; тогда фронтенду нужно указать адрес API через прокси того же
домена (браузер не должен обращаться к localhost или внутренним адресам).

Переменные окружения — см. `.env.example`: там только имена, значения вносятся в панели хостинга.
Обязательный минимум для старта: `API_PORT`, `WATCHTOWER_PROVIDER`, `SOLANA_CLUSTER`,
`WATCHTOWER_READ_TOKEN` (если API публичный).
